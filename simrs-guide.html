Master Data SIMRS — Pasien & Dokter

Halaman ini menjelaskan bagaimana form mengambil data master pasien dan dokter dari SIMRS, endpoint yang dibutuhkan, cara pemetaan field, serta cara mengonfigurasi dan mengujinya.

1. Alur data

User isi No. RM→ Tekan Enter→ fetchPasien(rm)→ GET SIMRS→ mapPasien()→ Form terisi otomatis
  • Pasien: field yang terisi otomatis = nama, No. Registrasi, tanggal lahir, jenis kelamin, alamat, no. telepon, penjamin, DPJP masuk, ruang, kelas.
  • Dokter: daftar nama dokter diambil terpisah dan dipakai mengisi <datalist> pada kolom DPJP Masuk / Nama DPJP Jantung.
  • Umur dihitung otomatis dari tanggal lahir terhadap tanggal tindakan.
  • Setiap pengambilan dicatat di audit trail (S.audit) sebagai bukti sumber data.

2. Konfigurasi endpoint

Edit blok SIMRS_CONFIG di form-input-lengkap.html, atau isi lewat browser tanpa mengubah file:

// di console browser
localStorage.setItem('cathlab:simrs', JSON.stringify({
  BASE_URL: 'https://simrs.example.go.id/api/rest',
  TOKEN:    'TOKEN_ANDA',
  TIMEOUT_MS: 8000
}));
Mode offline: bila BASE_URL kosong, form memakai data lokal (PASIEN_DB / DOKTER_DB) sehingga tetap bisa dipakai untuk demo tanpa koneksi. Ini perilaku bawaan di GitHub Pages.

3. Pemetaan field

Kalau nama kolom SIMRS berbeda, ubah satu objek ini saja:

const FIELD_MAP = {
  nama:     'nama_lengkap',   // → field form
  reg:      'no_registrasi',
  lahir:    'tgl_lahir',
  jk:       'jk',
  alamat:   'alamat',
  telp:     'no_telepon',
  penjamin: 'penjamin',
  dpjpMasuk:'dpjp_masuk',
  ruang:    'ruang',
  kelas:    'kelas'
};

Normalisasi otomatis

  • Telepon: tanda hubung/spasi dibuang → 0812-3456-7890 menjadi 081234567890 agar lolos pola validasi.
  • Tanggal lahir: bila format bukan YYYY-MM-DD, dikonversi ke ISO.
  • Kolom yang tidak dikirim SIMRS dibiarkan kosong — tidak menimpa isian pengguna.

4. Autentikasi & timeout

  • Bila TOKEN diisi, permintaan dikirim dengan header Authorization: Bearer <token>.
  • Semua request memakai AbortController dengan batas TIMEOUT_MS (default 8 detik) agar form tidak menggantung.
  • Kegagalan koneksi tidak menghentikan form: form jatuh ke data lokal dan menampilkan toast.
  • Rekomendasi: jangan menaruh token API di kode publik. Untuk produksi, arahkan ke proxy/backend yang menambah header server-side, atau pakai token sesi berumur pendek.

5. Menguji koneksi

Di bagian Identitas Pasien terdapat tombol Uji koneksi:

  • Offline (BASE_URL kosong) → menampilkan keterangan mode offline.
  • Terhubung → menampilkan jumlah dokter yang berhasil diambil.
  • Gagal / timeout → menampilkan pesan error dari server atau batas waktu.

Periksa manual dari console

await fetchPasien('00051563')   // data pasien
await fetchDokter()                // daftar dokter

6. Catatan keamanan & privasi

  • Data master hanya dibaca; form tidak pernah menulis ke SIMRS.
  • Data pasien disimpan di localStorage browser, bukan dikirim ke server mana pun.
  • Jangan menambah kolom sensitif (mis. diagnosis HIV, NAPK) ke PASIEN_DB yang ikut ter-commit ke repo publik.
  • Riwayat versi (Riwayat) juga menyimpan snapshot lokal di peramban yang sama.

GET  {BASE_URL}/MASTER/pasien/{no_rm}
  → { nama_lengkap, no_registrasi, tgl_lahir, jk, alamat,
      no_telepon, penjamin, dpjp_masuk, ruang, kelas }

GET  {BASE_URL}/MASTER/dokter
  → [ { nama_lengkap }, … ]   (atau array string)
